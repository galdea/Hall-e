# Windows implementation boundaries

Native WPF .NET 10 Windows edition, initial release 0.1.0. No macOS feature parity claims. All files live below windows/. Namespace HallE.Core for cross-platform models/library; HallE.Windows.Services for Windows services. Public API below is the integration contract.

## LibraryStore (parent owns HallE.Core)

Constructor `LibraryStore(string rootPath)`. Property `string RootPath`. Synchronous local operations, thread-safe and atomic writes. `IReadOnlyList<MeetingRecord> ListMeetings(string? query = null)`, `MeetingRecord GetMeeting(string id)`, `MeetingRecord CreateMeeting(string title, string? projectId, string language, CaptureMode mode)`, `void SaveMeeting(MeetingRecord meeting)`, `IReadOnlyList<ProjectRecord> ListProjects()`, `ProjectRecord CreateProject(string name)`, `string GetAudioPath(string id)` (audio.wav), `string GetMeetingDirectory(string id)`, `string GetNotes(string id)`, `void SaveNotes(string id, string notes)`, `string GetTranscript(string id)`, `void SaveTranscript(string id, string text)`, `string ExportMarkdown(string id)`, `void DeleteAudio(string id)` (preserves notes and transcript), `AppSettings LoadSettings()`, `void SaveSettings(AppSettings settings)`. No keys in settings. UI autosaves notes before switching meetings and closing. Metadata record updates use `with`.

## Windows services (services worker owns Services/)

`sealed class AudioRecorder : IDisposable`: `bool IsRecording`, `event Action<float>? LevelChanged`, `event Action<string>? Warning`, `IReadOnlyList<AudioDevice> GetMicrophones()`, `Task StartAsync(string wavPath, CaptureMode mode, string? microphoneId = null)`, `Task<CaptureResult> StopAsync()`. Write audio incrementally to disk, not whole meeting in memory. All-system audio is opt-in and explicitly described as all playing computer audio (not one application). Any capture failure is visible, not silent fallback. Stop must await native capture callbacks before closing writers. A static recovery helper `void RecoverInterruptedAudio(string directory)` may repair own partial WAVs. Never delete originals on conversion failure.

`sealed class CredentialStore`: constructor `CredentialStore(string rootPath)`, `bool HasKey(TranscriptionProvider provider)`, `string? GetKey(TranscriptionProvider provider)`, `void SaveKey(TranscriptionProvider provider, string key)`, `void DeleteKey(TranscriptionProvider provider)`. DPAPI CurrentUser, never log/store plaintext.

`sealed class TranscriptionService`: constructor `TranscriptionService(LibraryStore library, CredentialStore credentials)`. `IReadOnlyList<string> GetLocalLanguages()`, `Task ValidateKeyAsync(TranscriptionProvider provider, string key, string region, CancellationToken cancellationToken = default)` (authentication only, do not save or upload audio); `Task<TranscriptionResult> TranscribeAsync(MeetingRecord meeting, AppSettings settings, IProgress<string>? progress = null, CancellationToken cancellationToken = default)`. Local uses installed Windows SAPI speech models with actual language selection; no online speech. Local unavailable -> clear setup message, never automatic cloud fallback. Deepgram/Speechmatics require saved key plus explicit provider consent. Speechmatics additionally training-disabled confirmation and region. Persist Speechmatics job ID and region immediately; retry/resume polls saved job instead of duplicate upload. On ambiguous submission failure never automatically resubmit. Preserve recorded audio on every error. Caller saves returned transcript with LibraryStore.SaveTranscript; service updates remote job metadata via LibraryStore. After transcription UI reloads metadata before updating Status to avoid erasing job ID. Cloud endpoints/payloads can be matched to existing Swift services.

## UI (UI worker owns App.xaml/.cs, MainWindow.xaml/.cs, SettingsWindow.xaml/.cs and own helpers)

Use the services/library API above. Attractive accessible WPF UI in Hall-e dark green/mint style. Native local-first workflow: welcome/setup, microphone selection, title and project, microphone-only default, explicit opt-in system audio with warning/consent, recording meter/timer and stop, library search, project assignment, note autosave, playback of audio.wav via WPF MediaPlayer, transcription choice/progress/cancel/retry, export notes+transcript Markdown, open library folder, delete audio confirmation preserving notes. Settings supports local language availability and optional cloud keys Save & test, separate audio permission, Speechmatics region/training confirmation. Clearly explain missing advanced Mac integrations and Windows preview status without implying the entire macOS app is ported. Never start recording or upload on launch. New instance should not conflict with active recorder. Close during recording asks and awaits stop; transcription cancellation preserves job metadata and recording. No shell execution of user-controlled text. Browser links/Windows settings only known fixed URLs. App startup `--smoke-test <result.json>` must initialize in isolated temp storage, show MainWindow without starting audio/cloud, write JSON success then exit automatically after loaded. Parent adds native installer tests.

No commits/push/deploy from workers. Parent owns projects, assets, core persistence/tests, packaging, workflow, website and publishing. Workers edit only their assigned files and report paths and real validation.
