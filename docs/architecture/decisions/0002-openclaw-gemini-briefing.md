# ADR 0002: OpenClaw Gemini Meeting Briefings

Status: Historical decision — accepted and implemented locally, user-approved
2026-08-09; retired from Hall-e on 2026-10-20.
Date: 2026-08-09

> **Retirement notice — 2026-10-20:** This ADR preserves the original approval
> and implementation history; it is not a current activation or recovery
> guide. The OpenClaw/Gemini structured-report integration was retired because
> it was unavailable and unreliable. Current Hall-e releases have no automatic
> report or retry path and no OpenClaw settings/activation flow. Existing
> briefing artifacts and historical schemas remain preserved. Generic
> configured AI-provider features keep their separate consent and are
> unaffected.

## Context

Gabriel approved using OpenClaw with Gemini models for automatic meeting analysis, but not the full system federation workflow. Existing direct Gemini enrichment is not durable and silently drops failures.

## Decision as originally approved (historical)

The 2026-08-09 design specified a dedicated OpenClaw agent ID `halle-reports` with:

- primary model `github-copilot/gemini-3.1-pro` (listed in the local OpenClaw model catalog at decision time);
- no messaging delivery;
- no delegation, gateway, browser, messaging, filesystem, shell, or external-action tools;
- a narrow system prompt that accepts transcript/context and returns only the versioned briefing JSON contract;
- isolated per-job sessions and bounded session cleanup.

The prior implementation wrote the prompt to a `0600` temporary file, invoked the local CLI through `Process`, and captured JSON output. Its historical command form was:

`openclaw agent --agent halle-reports --message-file <path> --model github-copilot/gemini-3.1-pro --json --session-key <derived-job-key> --timeout <bounded>`

The prior implementation removed the temporary prompt after capture. Canonical
results were stored in the recording folder. OpenClaw session copies were
operational artifacts, not canonical records, and could be pruned after 30 days
with agent-scoped session maintenance.

At the time, every briefing job was gated by independently revocable cloud transcript-text consent. The consent record named OpenClaw plus the selected GitHub Copilot/Gemini processor, included the policy/retention baseline and observation date presented at opt-in, and was re-confirmed when the processor or material terms changed. Revocation blocked new and resumed briefing jobs without changing completed transcripts or deleting canonical local artifacts.

The original decision rejected the Gateway OpenAI Chat Completions endpoint because its bearer token is a full operator credential, and rejected `/hooks/agent` because it is asynchronous and does not return the structured result directly to Hall-E.

## Historical briefing contract and schema

The historical contract defined structured JSON containing: headline, ranked
general objectives, individually owned tasks, explicit dates, decisions,
risks/blockers, open questions, next milestones, confidence, transcript hash,
prompt/model provenance, and evidence anchors.

Its rules required utterance/time evidence for substantive items; tasks used
`knownPerson`, `explicitName`, or `unassigned`; anonymous speaker numbers could
not become names without corroborating evidence; dates were `null` unless
explicitly stated or safely resolved from an explicit relative date and meeting
date. The schema and existing outputs are retained as history, not generated by
the current application.

## Options considered at the time (historical)

- Existing direct Gemini API: simpler but violates the approved OpenClaw execution requirement.
- Full system federation: rejected by Gabriel for routine automatic reports.
- OpenClaw HTTP Chat Completions: rejected because it exposes full operator access.
- OpenClaw webhook: rejected because accepted runs are asynchronous and do not synchronously return the report JSON.
- Local OpenClaw CLI with dedicated agent: selected; it uses the supported Gateway agent path, avoids gateway credentials in Hall-E, and returns machine-readable output.

## Consequences at the time (historical)

- OpenClaw and the selected Gemini model had to be available for report generation, while transcript completion remained independent.
- The design assigned briefing generation a durable job and retry state so it did not change a completed transcript to failed.
- Model ID, prompt version, transcript hash, and output schema were persisted for auditability.
- Model availability could change; the agent/model selection was configurable behind an explicit allowlist of Gemini-only models.
- Analysis cost and quota followed the configured GitHub Copilot/OpenClaw entitlement. Rate limits or exhausted quota paused the briefing job and surfaced action required; they did not trigger a non-Gemini or direct-provider fallback.
- Transcript-bearing OpenClaw sessions and provider-side copies were outside Hall-E's recording folder. Manual local meeting deletion enumerated local canonical/temporary copies but could not promise immediate deletion from provider systems; provider retention followed the consented baseline and provider terms then in effect.

## Rollback

Historical rollback note: the original plan was to disable automatic briefing
jobs while preserving transcripts and prior artifacts. The integration has
since been retired from Hall-e; do not use this ADR to reactivate it. Any future
reporting integration requires a new decision and explicit approval.

## Original reconsideration triggers (historical)

The selected Gemini model becoming unavailable, report quality failing
validation, inadequate CLI/Gateway reliability, or OpenClaw offering a narrower
synchronous scoped API were the original reconsideration triggers. Reliability
and availability concerns led to the retirement recorded above.
