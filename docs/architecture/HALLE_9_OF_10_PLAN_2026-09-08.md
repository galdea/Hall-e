# Hall-e: plan for a 9/10 macOS assistant

Date: 2026-09-08. Scope: planning only. No application code changed. Review covers the current working tree, including existing uncommitted work. Findings below come from source review; live UI, audio behavior and market position have not been validated. A baseline `make test` attempt produced no output and was cancelled; no test-pass claim is made.

The product should own one dependable loop: arrive prepared, capture reliably, and turn meetings into useful project memory and commitments. The biggest release risks are reminder correctness, recording lifecycle safety and identity consistency. Ship these before expanding assistant scope.

## Delivery sequence

1. **M1 — Trust and lifecycle:** H01–H06 and H10. Fix existing behavior before adding automatic silence stop; H03 depends on session guards and trustworthy activity signals.
2. **M2 — Daily workflow:** H07–H09 and H11. Implement meeting categorization, settings/navigation and recovery affordances.
3. **M3 — Intelligence and release proof:** H12–H15. Build on existing intelligence, remove personal defaults, package for distribution and validate with users.

M1 and M2 can overlap only across independent files; project ID migration precedes new assignment paths. No promised calendar dates without capacity/estimation. Every issue must inspect existing changes before editing, preserve user work, run its listed checks and report any unverified behavior.

## Experience contract

- Reminder: default T−5 minutes, gentle ring, meeting title/start/project, Join and Open meeting. Open meeting exposes select/create-project without blocking Join. Preserve existing custom lead settings.
- Capture: 20 observed seconds without voice → visible warning → 20-second countdown → safe stop. Stop now ends immediately; Keep recording cancels and waits for speech before rearming; resumed voice cancels the pending stop. Defaults configurable; capture failure and sleep are not silence.
- Settings: General; Meetings; Capture; Intelligence; Storage & Privacy; Advanced. Existing preferences migrate without resets.
- Workspace: Today/Inbox for daily work, Projects/Meetings for context, Actions/Search for retrieval and follow-through. People is a secondary directory. Menu bar stays focused on next meeting and active capture.

## H01 — Repair reminder reconciliation and delivery tracking

Priority: High. Milestone: M1. Recommended workflow: ChatGPT web — Extra high. Dependencies: none.

**Evidence / opportunity:** Verified: NotificationScheduler.swift:106 returns when notifications are disabled without cancelling pending reminders; :118 passes every pending identifier into meeting reconciliation. NotificationPlanner compares only identifiers, so changing lead time does not replace an existing request. NotificationDelegate marks delivery only on presentation/action and resolves start time through the current agenda.

**Proposed implementation:** Reconcile only owned meeting requests, model snoozes explicitly, cancel owned requests immediately when disabled, replace changed payload/fire time, reconcile system-delivered notifications using immutable occurrence metadata, and record scheduling errors instead of silently marking success.

**Acceptance and validation:** Regression matrix covers disable/re-enable, lead changes, reschedule, cancellation, declined/all-day events, repeated sync, background delivery, snooze surviving sync, timezone/DST, offline launch and wake. Never cancel recording prompts. No duplicate occurrence reminders.

## H02 — Deliver five-minute reminders with a gentle ring

Priority: High. Milestone: M1. Recommended workflow: ChatGPT web — Extra high. Dependencies: H01.

**Evidence / opportunity:** Verified: AppPreferences.swift:47 defaults to 15 minutes; NotificationScheduler.swift:135 uses the default system sound.

**Proposed implementation:** Default new/unset preferences to five minutes, preserve explicitly saved custom values, offer gentle/silent/system sound with preview. Bundle a short soft chime. Include meeting title, start time, project and Join/Open meeting actions. Open meeting routes to its inspector with project selection. Quiet hours and macOS notification permissions remain explicit.

**Acceptance and validation:** One eligible reminder at T−5 minutes under normal scheduling conditions; late sync sends one immediate reminder before the meeting begins. Test sound packaging in signed app, denied permission, Focus, mute and sleep/wake without promising delivery when macOS suppresses it. No automatic recording merely from a reminder.

## H03 — Implement configurable 20-second silence plus 20-second stop countdown

Priority: High. Milestone: M1. Recommended workflow: Codex — GPT-5.3-Codex high. Dependencies: H04, H05.

**Evidence / opportunity:** Verified: RecordingLifecyclePolicy.swift:57–63 suppresses repeat prompts but has no silence timeout; tests explicitly expect no stop after the prompt. A five-second initial grace currently shifts first detection.

**Proposed implementation:** Add explicit listening, awaiting confirmation, keeping, stopping and finished states, driven by a monotonic deadline and session-scoped events. Defaults: warn after 20 continuous seconds without detected voice; stop after another 20 seconds without response. Show countdown, Stop now and Keep recording in workspace/popover plus notification. Voice resuming cancels pending stop. Keep cancels countdown and suppresses another silence prompt until speech resumes. Settings expose enabled switch, silence interval (5–300s), response interval (5–120s), auto-stop toggle and reset defaults; reject invalid persisted values. Define initial capture settling grace separately and document it.

**Acceptance and validation:** Boundary tests at 19.9/20/39.9/40 seconds, Keep, Stop, resumed speech, simultaneous events, invalid settings, restart, sleep/wake and no notification permission. Exactly one finalization and one downstream processing job; audio retained. Do not count sleep as observed silence. Existing user preferences preserved. Local macOS validation required; ChatGPT web — Extra high can design/review the state machine.

## H04 — Distinguish speech, silence and capture failure before auto-stop

Priority: High. Milestone: M1. Recommended workflow: Codex — GPT-5.3-Codex high. Dependencies: none.

**Evidence / opportunity:** Verified: RecordingService.startTimer uses max microphone/system average power as voice proxy and stops after six seconds of process input/output inactivity via RecordingLifecyclePolicy. Power does not distinguish speech from fan noise/music; process inactivity is not definitive call-end evidence.

**Proposed implementation:** Introduce a local voice activity abstraction over mic and remote tracks with smoothing/hysteresis. Represent missing frames or capture failure separately from silence. Use explicit supported call-end signals where available; weak process-inactivity signals must not bypass the silence-confirmation policy. Clearly identify mic-only capture and unavailable remote audio.

**Acceptance and validation:** Consent-approved fixtures cover quiet speech, remote-only speech, muted mic, fan noise, keyboard, music, dropped frames, device unplug, route switch and actual call end. Measure false stop rate; zero false stops in release fixture matrix. Bound CPU cost. Hardware validation required; web Extra high supports design and fixture review.

## H05 — Bind recording notifications and asynchronous callbacks to session identity

Priority: High. Milestone: M1. Recommended workflow: ChatGPT web — Extra high. Dependencies: none.

**Evidence / opportunity:** Verified: NotificationScheduler.postRecordingPrompt has a fixed identifier and only prompt kind in userInfo; NotificationDelegate.swift:25–32 acts on the current singleton recording. RecordingService delegate callbacks and delayed cleanup also lack session identity guards.

**Proposed implementation:** Attach immutable session ID and prompt generation/deadline to notification requests, responses, delegates and delayed cleanup. Ignore stale actions, remove delivered/pending prompts on resolution, and prevent callbacks from an old recorder changing a new session.

**Acceptance and validation:** Start A, show prompt, stop A, start B, click A Stop/Keep/Extend: B is unchanged. Duplicate response, late delegate, delayed cleanup and concurrent end/silence signals finalize the correct recording once.

## H10 — Finalize recordings safely on quit and recover interrupted capture

Priority: High. Milestone: M1. Recommended workflow: Codex — GPT-5.3-Codex high. Dependencies: H05.

**Evidence / opportunity:** Code-review risk: StatusItemController.swift:128 terminates directly and reviewed AppDelegate has no applicationShouldTerminate recording-finalization guard; session metadata saves are best effort. Runtime loss has not been reproduced.

**Proposed implementation:** Coordinate app termination with bounded audio flush and durable session checkpoint. Recover interrupted sessions on launch without silently discarding original tracks or duplicating paid processing. Surface disk-full/write failures, sleep and device-change state. Include user choice to cancel quit while recording.

**Acceptance and validation:** Test quit, logout path, crash after checkpoint, disk full, permission loss, corrupt session JSON and restart; retain recoverable media and honest status. 100 scripted sessions with zero lost/corrupt finalized recordings before release. Web Extra high prepares failure matrix; local macOS runner required.

## H11 — Give processing failures an actionable recovery inbox

Priority: Medium. Milestone: M2. Recommended workflow: ChatGPT web — Extra high. Dependencies: none.

**Evidence / opportunity:** Existing foundation: InboxWorkspaceView handles classification/transcription/sync/vault attention; reviewed service code uses try? for several refresh/persistence paths. Audit which failures currently reach users before changing behavior.

**Proposed implementation:** One per-recording pipeline timeline: capture → transcribe → summarize → file. Show durable status, last successful stage, actionable failure, Retry and provider/settings deep link. Preserve manual/consent controls and distinguish queued versus failed. Deduplicate retries and expose budget/consent blockers.

**Acceptance and validation:** Offline and provider outage recover without duplicate output or charges where provider idempotency permits; no silent indefinite spinner. Failure injection verifies status and remedy per stage. Never claim exact-once remote billing without provider support.
