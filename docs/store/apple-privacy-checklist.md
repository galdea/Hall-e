# Apple App Privacy submission checklist (Mac App Store)

App Privacy is published in App Store Connect for six data types. Use this as a source-based review aid to verify that declaration against the exact candidate and current provider settings; it is not a substitute for that evidence. Apple requires the label to cover data collected by the app **and third-party partners**. “Collect” includes sending data off-device where the app or partner can access it beyond the time needed to serve the live request. Do not choose “Data Not Collected” just because Hall-e has no developer-operated backend or cloud features are optional. [Apple: App Privacy Details](https://developer.apple.com/go/?id=info-1) · [Manage app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy)

## What the Mac App Store build enables

- `MAC_APP_STORE` is set by `scripts/build.sh mac-app-store`. `DistributionCapabilities` disables process/system-audio capture, Chrome native messaging, Codex home import, and external archive processing. Recording uses the microphone; Apple Speech is the on-device transcription path. The OpenClaw/Gemini structured-report integration was retired from all Hall-e editions on 2026-10-20; preexisting report artifacts remain local. This retirement does not disable the separate generic configured AI-provider features below.
- Recordings, transcripts, notes, projects, calendar cache, settings, and credentials are stored locally in the sandbox container and Keychain. The user-selected notes folder uses a security-scoped bookmark. These local-only paths do not by themselves establish that data is “collected” under Apple’s label definition.
- Optional cloud transcription can send meeting audio to Deepgram or Speechmatics after provider setup and explicit audio permission. Automatic mode can choose an authorized cloud provider; “On this Mac” selects local transcription for new jobs. Existing remote jobs keep their original provider. The app requests Deepgram model-improvement opt-out; Speechmatics is gated on user confirmation that Model Training is off and a selected processing region, and the UI says audio/job data may remain there up to seven days. These provider-side settings and terms must be verified against the actual accounts and current provider documentation before submission.
- The optional AI settings support OpenAI, OpenRouter, Anthropic, Gemini, local Ollama/LM Studio, and a custom OpenAI-compatible endpoint. AI features can transmit transcript text, event/project context, or selected project material according to enabled provider settings and their existing consent. In particular, `TranscriptPostProcessor` may run automatically after a fresh transcription when AI Providers are enabled and cloud transcript consent is active; do not assume a new invocation or consent prompt for each transcript. Other AI features may be user-initiated. The retired OpenClaw/Gemini report pipeline creates no new reports or retries; it does not remove generic Gemini or other configured AI-provider features. Local Ollama/LM Studio configurations need endpoint/network verification before deciding whether data leaves the device.
- Calendar access is optional. The Store path uses macOS Calendar/EventKit and reads only calendars selected by the user. The app also contains an advanced Google Calendar OAuth/API path; verify whether it is reachable and exposed in the submitted Store build, and include it if users can use it. Calendar contents and meeting metadata may be downloaded into the local cache.
- The 0.5.0 candidate adds an optional developer-operated shared-session coordinator, hosted on Cloudflare Workers. When users explicitly pair devices and share meetings, title, optional project name/link, and scheduled times are encrypted on device and transmitted to paired devices; the service stores ciphertext plus device/workspace/session/segment IDs, display names, timestamps/status, credential hashes, and recording-lease metadata. It does not receive audio or the encryption key. Cloudflare may process network/request metadata as infrastructure provider; account-specific platform logs and retention depend on deployed configuration. Include this service and its infrastructure provider in the exact-candidate data inventory and label analysis; do not claim no developer-operated backend or “Data Not Collected” without completing that analysis.

## Complete before answering App Store Connect

- Build and inspect the exact Store archive/release configuration. Confirm the compile flag, visible settings, enabled code paths, bundled dependencies, and actual outbound network destinations. Do not infer Store behavior from the direct-download build.
- For each enabled remote provider, record the exact provider, endpoint, model, account plan, region, retention/deletion rules, training/improvement controls, and whether request data is retained beyond real-time service. Cover the provider’s own onward processors and terms. “User supplies the API key” does not make the provider’s collection irrelevant.
- Review each AI action and payload in code (for example summaries, transcript post-processing, project intelligence, and transcript-based renaming). Determine which personal-data categories those payloads contain, the stated app purpose, and whether Apple’s “linked to the user” criteria apply. Consider meeting audio/transcripts and calendar titles, attendee names/emails, links, and project content; classify only after inspecting actual payloads and provider practices.
- Decide whether Google OAuth/API calendar sync is available in this build, and document access scope and provider handling. Distinguish Google’s processing from any data Hall-e itself receives or stores.
- Confirm whether any telemetry, crash reporting, analytics, or other SDK collects data in this build. Verify coordinator and Cloudflare account configuration outside this repository before making claims about network logs or retention.
- Use Apple’s categories, purposes, linkage, and tracking definitions for every data type that the app or a partner collects. Optional features still count if users can enable them. If data is not accessible beyond real-time service, assess Apple’s exception against the actual provider behavior rather than assuming it.
- Keep the public privacy policy accurate about Store-specific behavior, providers, retention/deletion, consent revocation, and support/contact. Revisit the App Privacy label whenever provider choices, endpoints, defaults, integrations, or app behavior change.

Apple references: [App Privacy Details](https://developer.apple.com/go/?id=info-1), [App Store Review Guidelines §5.1.1](https://developer.apple.com/app-store/review/guidelines/), and [privacy manifests / data-use descriptions](https://developer.apple.com/documentation/bundleresources/describing-data-use-in-privacy-manifests). This checklist does not determine the final label; provider account configuration and collection/retention terms remain decisions and evidence the app owner must supply.
